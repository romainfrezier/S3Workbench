## Large download and interruption

The existing synthetic `large-512MiB.bin` fixture contains 536,870,912 zero bytes.
It was downloaded through Command-S to a temporary directory. The transfer
popover visibly progressed and then reported Completed. On-disk byte count and
streamed SHA-256 verification both passed:

`9acca8e8c22201155389f65abbf6bc9723edc7384ead80503839f49dcc56d767`

[Memory and integrity observation](2026-09-21-large-download-observation.json)
records 300 process-RSS samples spanning the first download. Baseline RSS was
143.94 MiB; the maximum observed was 159.58 MiB, a 15.64 MiB increase while
downloading a 512 MiB object. Samples were taken approximately every 0.21 seconds.
This is a sampled observation for this file, build and machine; it neither bounds
unobserved peaks nor proves a transfer larger than available RAM or a Finder export.

A later download was suspended by pausing only the existing QA MinIO container
after 11,911,168 bytes had reached its temporary `.download` file. The app showed
about 3.2% progress. The attempt to click Cancel failed with the automation error
`noWindowsAvailable`; activating the exposed transfer row and keyboard traversal
did not establish cancellation. A 45-second watchdog resumed the QA container.
The same transfer then completed with the exact SHA-256 above and no leftover
temporary download. This proves recovery after a suspended server, **not Cancel
or Retry**. Three completed downloads were checked, including the earlier timing
attempt that finished before a pause; their isolated directories are in the
observation record.

## Limits and remaining work

- Closing Settings initially produced `noWindowsAvailable`/`timeoutReached`
  from UI automation. Command-comma restored access to Settings; a full app
  restart restored normal main-window control. No root cause or fix is claimed.
- Some transient menus were lost between inspection and activation. The
  multi-file context action succeeded when activated immediately from its
  freshly observed menu. A lingering Navigate menu required its native Cancel
  accessibility action. These automation boundaries are not product regressions.
- Command-left-bracket did not navigate with the search field focused in this
  run. Toolbar Back/Forward passed, but keyboard layout/input delivery versus
  application routing was not isolated. Keyboard coverage remains incomplete.
- Signed-link lifetime persistence and main-window appearance passed in the
  follow-up above; the initial menu-activation limitation was worked around by
  activating the freshly observed menu item in the same interaction.
- [#16](https://github.com/romainfrezier/S3Workbench/issues/16): no cross-application
  Finder/Desktop drag completed. Downloading and inspecting files in Finder do
  not prove file promises, deferred download, large-export memory, cancellation,
  incoming upload gestures or stale drag contexts. An attempted drag from the
  observed file icon to an unsupported area of the same table also returned
  `noWindowsAvailable` before a gesture was established. No no-request-before-drop
  pass is inferred from that failed attempt. Cancel and Retry remain unvalidated.
- [#17](https://github.com/romainfrezier/S3Workbench/issues/17): adding a connection
  from scratch, injected save/delete persistence failures and VoiceOver remain
  outside this pass. Duplicate/delete, scoped index clearing, main-window appearance
  and link preference persistence now have the evidence above.
- [#15](https://github.com/romainfrezier/S3Workbench/issues/15): complete focus and
  multi-window shortcut coverage, other command entry points and VoiceOver remain
  outside this pass.
- [#19](https://github.com/romainfrezier/S3Workbench/issues/19): this run establishes
  rebuild/edit/submit/clear behavior. It does not repeat all cancellation, failed
  rebuild, restart, pagination/reveal and multi-window scenarios recorded in
  earlier local sessions; it is not a release-package or VoiceOver pass.
